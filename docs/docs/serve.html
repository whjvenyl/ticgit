Web View

Command: ti serve

ti serve starts a small read-only HTTP server that lets you browse your tickets in a web browser. No external dependencies, no database — it reads from the same git-meta store as the CLI and TUI.

SERVE
$ ti serve
ti serve: listening on http://127.0.0.1:8177/ (ctrl-c to stop)

Open the page automatically in your browser:

SERVE & OPEN
$ ti serve --open

Options

OPTIONS
$ ti serve --port 8080 --bind 0.0.0.0 --open
  • --port / -p — port to listen on (default 8177, use 0 for a free port)
  • --bind — address to bind (default 127.0.0.1, use 0.0.0.0 to share on your network)
  • --open — open the page in your browser on start

Views

The web view has three modes, switchable from the nav bar. All views share the same filters (status, state, tags, assigned, search), so you can narrow to e.g. ?tag=bug and see only bug tickets in any view.

List

The default view at /. A sortable table of tickets showing id, age, priority, state, title, assignee, and tags. Click a ticket to see its detail page at /t/<id>.

LIST VIEW
$ ti serve
# opens at http://127.0.0.1:8177/
# table with sortable columns, filter chips, search

Kanban

A board view at /kanban. Tickets are grouped into columns by lifecycle state:

KANBAN VIEW
$ ti serve
# navigate to /kanban or click "Kanban" in the nav
 
new assigned in-progress blocked review
+------ +------ +------ +------ +------
| card | | card | | card | | card | | card |
+------ +------ +------ +------ +------

Each card shows the ticket id, title, priority, assignee, and tags. Click a card to open the detail page. Empty closed-state columns (resolved, wontfix, etc.) are hidden to reduce clutter; they appear when closed tickets match the active filter.

Flow

A dependency graph view at /flow. Tickets appear as nodes and their relationships as edges, rendered with React Flow loaded from a CDN (no build step required).

FLOW VIEW
$ ti serve
# navigate to /flow or click "Flow" in the nav
 
[parent] ----dashed----> [child]
[ticket] ----solid-----> [dependency]

Edge types:

  • Solid animated — dependency edges (depends_on). Ticket A depends on ticket B.
  • Dashed — parent/child edges. Parent ticket links to its sub-issue.

Nodes are positioned in columns by state (like the kanban). The view is read-only: nodes aren't draggable, but you can pan (drag) and zoom (scroll). Click a node's id to open the detail page.

Filtering

All three views accept the same query parameters as ti list:

FILTERS
$ # open in browser:
http://127.0.0.1:8177/?tag=bug
http://127.0.0.1:8177/kanban?state=blocked
http://127.0.0.1:8178/flow?assigned=you@example.com&all=1

Supported params: status, state, tag (repeatable), assigned, q (search), order, all, subissues.

JSON API

/tickets.json returns the filtered ticket list as a JSON array, accepting the same query params:

JSON
$ curl http://127.0.0.1:8177/tickets.json?tag=bug
[{"id":"a3f...","title":"fix parser",...}]

Detail Pages

Each ticket has a detail page at /t/<id> showing all fields, description, spec, and comments. The id can be a full UUID or any unique prefix.

DETAIL
$ # open in browser:
http://127.0.0.1:8177/t/a3f
